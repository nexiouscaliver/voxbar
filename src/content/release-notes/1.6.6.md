## Fixed: A Dead Phone's Lane Retires Only When Its Work Is Done

When a phone hangs up mid-dictation, the Mac retires that phone's lane:
its recorder, its audio state, its cancel wiring. The retirement
decision used to be inferred from the dictation machine's apparent
stage, so a stop path that reset the machine early could sweep the
lane's audio while its transcript pipeline was still draining.
Retirement is now decided by the pipeline registry itself: a lane with
a transcript still in flight is never retired, and the moment its
pipeline finishes, its own completion drain re-runs the retirement, so
the cleanup lands on a fully drained lane no matter which stop shape
got there first.

The retirement probe that runs after every dictation no longer touches
the connection lock on the common path: a live phone's probe is a
lock-free set lookup, and only a lane whose socket actually died ever
polls the connections. Dead ends that could strand a lane past its
retirement are closed with it. An Escape press that lands after the
phone is already gone now feeds the same deferred cleanup instead of
leaking the machine, a press remembered across a phone drop can no
longer restart a recording on a lane whose connection is gone, and
turning the phone server off mid-flight queues the cleanup for every
lane it clears, so a connection that dies without a farewell cannot
block its own lane's retirement.

## Fixed: The Paired-Phone Record That Nothing Read

Two releases ago the Mac began keeping a durable record of every phone
you paired, seeded at startup and saved on every pairing. An audit of
every reader found the record was write-only: the tray's paired count
reads live connections, and a phone's Recent list entry keys on the
identity the phone itself presents, so the saved list fed nothing but
its own newness check, the check that decided whether to save the list
again. The whole apparatus is deleted, the startup seed, the save
worker, the newness check, and the settings entry they maintained, and
its races go with it. The removal is rollback-safe: a settings file
that still carries the old entry loads cleanly and drops it the next
time settings are saved.

## Fixed: The Last Settings Read Leaves The Connection Task

Phone connections run on the app's async runtime, whose workers must
never sit in a synchronous wait, or a slow one pins the worker every
new connection needs. Four blocking-pool seams already existed to keep
that work off the connection task; the fifth was still inline: every
press and release of the phone's talk button re-read the activation
mode and hold threshold on the task itself, touching the settings
store's mutex, whose migration and recovery legs can write the store
back synchronously while holding it. That read now rides the blocking
pool like its four siblings, so the connection task never touches the
settings store, and an activation change made mid-connection is
honored by the very next press instead of a connect-time snapshot.

## Fixed: A Flapping Phone Pays One Tray Rebuild, Not One Per Hop

Every phone connect and disconnect used to spawn its own full tray
menu rebuild: a settings read, the model list, an icon decode. A phone
whose network flaps, reconnecting every few seconds, paid a complete
rebuild per hop, and each result was stale the moment the next hop
landed. Both edges now feed a coalescing gate: the first edge in a
quiet spell claims the rebuild, edges that land while a rebuild is
live only mark it pending, and the claiming rebuild loops until
quiet, always reading live state, so the final pass always matches
the settled set of phones. At most one rebuild runs at any instant and
at most one per settled state, and a rebuild that fails releases the
gate, so a broken refresh can never freeze the tray menu.

## Behind The Scenes

The engineering defect ledger that has driven this release line is at
zero open items: the twenty verified findings the stabilization fleets
queued after v1.6.4 are all closed, each pinned by a test, and the
ledger's own suite now checks that the queue stays closed and that
every code citation in an entry points at code that still exists. The
one verdict not closed is deliberate: the ggml duplicate-symbol
warnings documented last release belong upstream, and the constraint
stays written down for whoever revisits.
