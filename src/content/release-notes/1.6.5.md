## Fixed: Phone Lanes Clean Up After Harder Failures

Turning the phone server off while a Mac-side dictation was still
running used to skip closing the recorders the server keeps pre-warmed
for phones, and nothing came back to close them once the dictation
ended. The skipped close is now parked and runs as soon as no recording
is left anywhere, and turning the server back on clears a parked close,
so it can never run against the fresh server. When a phone disconnects
mid-dictation, the forced stop no longer sits out the audio release
window that only a live phone can fill: a lane whose phone is already
gone pays no wait, while a live lane keeps the window exactly. And the
lane maps on the audio path no longer die with a panicked task: the
lock recovery the connection path got last release now covers every
audio-side lock, so one panic cannot wedge every later phone recording.

## Fixed: Model Actions Report Their Failures

Deleting a model or cancelling a download used to fail silently: the
confirmation dialog closed, nothing happened, and the reason went only
to the developer console. Both actions now report the failure in the
settings row, with the error spelled out, in all 26 languages. A
refusal because a dictation is still live keeps its own dedicated
message.

## Fixed: The AI Message Names The Real Reason

The Apple Intelligence availability check used to answer yes or no, so
a build of the app that does not include the AI engine told every user
their macOS was too old, which was not true. The check now answers
three ways: available, this macOS lacks it, or this build lacks it,
each with its own sentence in settings and in Prompt Studio, in all 26
languages. A check that fails to answer at all now says availability is
unknown instead of making a claim about your macOS it cannot support,
and where the studio row clips the full sentence, the whole text is
reachable through the row's tooltip.

## Fixed: An Armed Recorder Survives An Implementation Switch

Switching the keyboard implementation while a VoxBar Keys dictation was
running unregistered the old backend without stopping the armed
recorder: the recorder survived the switch armed, and the next start
refused with Already recording. The switch now force-stops an armed
recorder first, through the same stop path the recorder's own command
uses.

## Fixed: Escape Cannot Stay Claimed After Its Session Dies

A timing race between one dictation tearing down and the next starting
could leave the Escape claim armed after every session had ended: a
dying session's claim registration could land after its own teardown
had already released that claim, re-arming it with no session left to
release it. The registration now checks the session's own liveness
under the same lock as the claim itself, for a phone lane's key and the
keyboard's own alike, so a session that is already dying cannot re-arm
a claim no one will ever release.

## Fixed: A Round of Smaller Repairs

- Resetting phone pairing used to report failure only to the developer
  console, leaving the panel showing a clean Stopped. A reset that
  fails now surfaces on the same error line a failed restart uses, and
  the panel says so when the reset could not be saved.
- The amber labels in the debug tables, the skipped and unchanged
  outcome legs and the live log's WARN tag, sat at 3.08:1 on the light
  background, under the 4.5:1 minimum; they now carry the darker amber
  at 4.85:1.
- Arabic has a dual form for exactly two, and the dual noun already
  says two, so a rendered count beside it read wrong. Every Arabic dual
  form now uses the bare dual, except the one whose count sits in
  parentheses with no noun to number.
- The phone's Polish text toggle takes effect from the next dictation,
  because a session freezes its settings at start, but the toggle never
  said so. The row now carries a hint line, shipped in all 26
  languages.
- Three settings writers, the pairing token rebind at server start, the
  pairing reset, and the log level, used to read the whole settings
  file, change one field, and write it back with no lock, so a
  concurrent writer could overwrite one side's change. All three now
  ride the same serialized read-modify-write cycle the pairing fields
  already used.
- The web layer's default opener permission granted every command the
  opener plugin offers, including ones that open arbitrary paths, while
  the app only ever opens links. The grant now names exactly the two
  URL permissions, so no arbitrary-path open command is reachable from
  the web layer and every link in the app keeps working.

## Behind The Scenes

The transcription engine and the local post-process AI engine each
vendor their own copy of the ggml math library, so a release build logs
ten duplicate-symbol warnings while linking. The link itself is sound
(the linker keeps the first definition) and the warnings are cosmetic,
but the fix is not in this app's hands: the two vendored library
versions skew apart, neither engine crate at the versions we pin offers
a seam to share or skip its copy, and the one local workaround would
change how the app bundles its libraries. The constraint is now written
down for whoever revisits: the clean fix needs the upstream
transcription crate to gain a way to build against a ggml it did not
vendor, with the two vendored versions aligned.
