## Fixed: The Stop-Wedge Fix, Completed

The previous release stopped the settings store from panicking and
contained stop-pipeline panics, which were real faults the diagnosis
captured on record. But the freeze itself could still recur after a
phone dictation: thread samples of the wedged app, taken with full
symbols, showed the teardown path, the tray refresh threads, and the
phone recents broadcast all queued on the same companion connection
lock, with no thread anywhere in the process holding it.

Two structural changes remove every path through that lock from the
teardown:

- The tray's paired-phone count is now a lock-free counter. Every menu
  rebuild reads it, including the teardown's own tray update, so the
  teardown never waits on the connection registry.
- Sending a frame to a phone now holds the connection registry only for
  the lookup: the sender is cloned under the lock and the send happens
  after the lock is released, so even a strand inside a channel send can
  never pin the registry for other readers.

With both changes in place, the teardown, the tray, and the phone
delivery path no longer share any lock at all. The fix carries a
machine-checked source pin for both legs, and the wedge rig that
reproduced the freeze on demand now runs three consecutive phone
sessions clean.
