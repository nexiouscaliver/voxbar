## Fixed: Phone Dictation Sessions Ending With No Audio

A single tap on the phone's talk button could register as two taps:
browsers fire both pointer and touch events for one press, and the second
cycle instantly ended the session the first one started, so everything you
said after that was dropped and the session closed with nothing transcribed.
The button now listens on exactly one event source, and the server logs any
audio that arrives outside a live session so this class of problem is
visible immediately.
